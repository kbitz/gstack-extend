# `/review-and-prep` run-state caller procedure (`run-state=record`)

## Status

Experimental until Track 79A's default decision, like `bin/review-state` ([design D1](designs/review-run-state.md#d1-roles)); read once at Step 1 only under `run-state=record`. Under the value, receipts, PR text and handoff lines are rendered with `bin/review-state render` from the recorded state, and any output the helper refuses is written as today. Upstream `/review` is wrapped, never edited. The state file is internal: external readers keep reading the published receipts and handoff lines, never `review-run-state.json`.

## Activation

Active when the review policy parsed with `run-state=record` and `"<extend-root>/bin/review-state" --version` exits 0 (`src/review-state/cli.ts` prints `review-state <version|unknown>` and exits 0), resolving `<extend-root>` from the installed skill's `.extend-root`. Otherwise the full receipt says `Run state: unavailable (helper-missing)` and the invocation runs today's inline path in full, the **Workflow metrics (optional, local)** section included.

## Directory, inputs and IDs

`--dir` is the invocation's evidence directory (**Capture evidence and commit**), created with `mkdir -p` before `start` (the helper never creates it, [design D2](designs/review-run-state.md#d2-location)). Each `--input` is an absolute path to a JSON file written into that directory with the file-write tool. IDs (`run_id`, `pass_id`, `attempt_id`, `correction_id`, `gate_id`, `audit_id`, `checkpoint_id`) are minted as the Workflow metrics section mints IDs today (fresh lowercase random UUIDs); voice IDs and `found_by` follow its attribution bullets (`skills/review-and-prep.md`). Request shapes: `"<extend-root>/bin/review-state" <command> --help` and [design D13](designs/review-run-state.md#d13-request-shapes-and-walkthrough). Evidence files a record names live inside the evidence directory. Issue calls one at a time from this session, from inside the work tree.

## Derive and spans

Run `"<extend-root>/bin/gstack-extend-telemetry" derive --dir <evidence directory>` from the work tree after `start` and each `checkpoint resume`, immediately before each receipt's `metrics read`, and after the pause checkpoint or `finish` and before Telemetry finish ([docs/telemetry.md](telemetry.md#review-state-derive), Review-state derive). It writes the run `begin`, `pass`, `correction` and run `end` records and any missing `stage-runs` rows; the model writes none of those. In the call that runs the first derive of a segment, resolve `GX_LIB` with the Workflow metrics section's resolver snippet; set `GX_RUN` from `data.current.run_step_id`, `GX_SID` from `data.current.session_id`, and `GX_CAPTURE=1` only when `data.current.run_begin` is `recorded` or `replayed`. Spans, waits and decisions stay as the Workflow metrics section says, with no context-override argument; fix-cycle corrections and attempt `model_context` are not derived (accepted measurement difference, decision d8). Each receipt's `metrics read` uses `data.current.session_id`. Derive's non-`ok` output goes in chat only; a later derive recovers a missed write.

## The baseline fence

While the state is being recorded, run the `cycle-1-baseline` fence with `REVIEW_STATE_DIR` set to the evidence directory for that call only. On `refused cycle-1-baseline: write point not reached (<id>)`, record the named voice result or `probe-<id>` gate and rerun the identical write; never write the baseline around it. Once the state is unavailable for the rest of the invocation, run the fence without `REVIEW_STATE_DIR` so a degraded run never blocks its own `cycle-1-baseline` write.

## Degraded path (design D1)

On a helper result with `retry: "same-input"` (`busy` or `unwritable`; wait `retry_after_ms` when present) or no parseable result line, rerun the identical command once. If it still fails, or on `bad-dir`, `unreadable` (`corrupt` or `newer-schema`) or any other refusal, record no further state for the rest of the invocation, stop setting `REVIEW_STATE_DIR`, keep today's outputs, and add `Run state: unavailable (<reason>)` and `Workflow metrics (local, optional): capture=partial (run-state unavailable: <reason>).` to the full receipt. Never delete a lock or repair a state file: `busy` recovery is manual ([design D8](designs/review-run-state.md#d8-commands-result-envelope-and-reason-codes)). On success the full receipt carries `Run state: recorded (<state path>; rev <n>)`. A render refusal, or a result line still missing or `retry: "same-input"` after the section's single retry, writes that one output inline; state recording continues. When the failed output is the full receipt, the inline full receipt carries `Run state: render unavailable (<output>: <reason>)`; a later output's failure goes in the exit message's prose in that same form, because the full receipt is never rewritten (`### Readiness`) and the rendered outputs already cite its SHA-256. This implements D14's opt-in-period caller behaviors; every other D14 item stays placed in Track 79A.

## Receipts and handoffs

Render outputs with `"<extend-root>/bin/review-state" render --dir <evidence directory> --input <file>`; inputs per output as `render --help` and [design D13](designs/review-run-state.md#d13-request-shapes-and-walkthrough) list them; the success line's `files[0].path` is the file to post with `--body-file` or splice. `Prepared HEAD:`, `Review handoff:`, `Delegated part:` (12 segments) and `delegation: active (…)` stay byte-exact ([design D9](designs/review-run-state.md#d9-derivation-map) and its "Orchestrator gate-read compatibility" note), as do the other kept lines. Sections and the body summary are files in the evidence directory holding only model-written parts (D9's full-receipt row list; the body's what-changed, `Review default:`, `Auto-chosen` lines, `Tests:` line and risks), never a line the renderer writes, and the summary has no `## ` line or `<!-- review-and-prep:` marker. Supply `pr` and `gh_login` (start's shapes) in a `final` input when `start` recorded them as `null`. Before posting a rendered comment, read it (the credential and PII scan already reads those bytes); a line that contradicts the run, such as an `Unresolved:` finding already fixed or a check listed as not run that ran, means a record is missing: record it and render the full receipt and comment again, or write that output inline when the state cannot hold the fact. Greptile-exit and configuration pauses keep today's inline text. Render only while state recording is active: after the Degraded path stops recording, or on a helper-missing activation, every output is inline as today. Measure the spliced body with Step 3's `PR_BODY_SIZE` check as today.
