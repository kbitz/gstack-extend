# Review evidence envelope — fact-to-reference mapping

## Role and source snapshot

This supporting design maps review facts from upstream `gstack` and `gstack-extend`'s `/review-and-prep` wrapper to upstream's portable evidence bundle (`gstack-evidence-bundle` v1) and the published stage-handoff records. It supports [SPEC](../SPEC.md#o4-publish-the-orchestration-contract) O4.3–O4.4 provenance for the **1.0.0** target and [workflow efficiency program](workflow-efficiency-program.md#selected-work) items E10–E11 (together with E14's write-once cycle-1 baseline record).

Existing upstream and wrapper contracts remain sole authorities. This document specifies how their artifacts and predicates relate so an orchestrator or human reviewer can evaluate full-review completion, freshness, and missingness from one reference without conflating them; it introduces no envelope runtime, parser, schema, CLI flag, readiness gate, skill change, or receipt-grammar change. All existing callers—`/review-and-prep continue`, `/ship-and-land`, H-E orchestrator consumers, `gstack-review-read` dashboards, and `gstack-tree-receipt` lane-reuse consumers—remain unchanged.

Key source-backed distinctions:

- **Commit, tree, and working-tree identity stay separate.** `bin/gstack-review-log` (`L55-L82`) and `bindReview` (`lib/review-evidence.ts:267-273`) stamp `commit_full` and `tree` from Git, while `commit` is caller-supplied display text. `wtree`, `review_binding.start_wtree`, and `review_binding.end_wtree` come from `bin/gstack-wtree --review` and capture working-tree content. Because uncommitted or untracked edits change `wtree` without moving `HEAD`, equal `HEAD` or `commit_full` never establishes freshness (`bin/gstack-review-read:8-10`).
- **Scope normalization is producer-specific; boolean and string completion types differ.** In upstream `lib/review-evidence.ts` (`L267`, `L310-L319`), a normal full pass omits `scope`, whereas a `--fix-range` start stamps `scope: "fix-range"` (and `fix_base`, `test/review-fix-range.test.ts:127-173`). Treating an omitted `scope` as full scope is valid only for rows produced by this sourced logger alongside `review_binding.state === "verified"` and the other predicates below; absence of `scope` on an unknown or legacy row is not positive proof of a full pass. Upstream review rows store `completed` and `converged` as booleans (`true`/`false`), whereas `/review-and-prep`'s internal JSON records require exact strings (`completed`: `"true" | "pending-fix-review" | "false"`; `fix_reviewed`: `"true" | "false"`, `skills/review-and-prep.md:2371,2389`). `cycles` counts editing passes (`review/SKILL.md:888-889`), not reviewer calls or findings.
- **Logger binding proves tree capture, not reviewer comprehension.** `bindReview` strips all caller-supplied binding and derived status fields (`commit_full`, `tree`, `wtree`, `dirty`, `review_binding`, `review_freshness`, `shared_libs_coverage_version`, `status_source`, `findings_total`, `findings_open`, `findings_resolved`, `findings_file`, `scope`, `fix_base`, `lib/review-evidence.ts:267`) and derives `status`/`unresolved`/`issues_found`/`critical_gaps` from `--findings` when supplied (`L251-L264`). As `bin/gstack-review-log` (`L20-L22`) states explicitly, `completed` and `converged` remain reviewer-reported claims, not proof that a model read the code.
- **Bundle reference and structural gap.** `EvidenceBundle` (`lib/evidence-bundle.ts:39-48`) has no first-class fields for review-log rows or wrapper baseline records. Do not encode reviewer prose as a synthetic passing test lane or add custom keys to `EvidenceBundle`. Instead, reference the existing `EvidenceBundle` alongside the sourced review records. As design metadata (without altering wire or receipt grammar), a portable artifact reference pairs an immutable locator with its exact-byte `sha256` digest, producer/source revision, and bound `commit`/`tree` (plus `wtree` when applicable). A digest proves which bytes were read, not the author's authority; a bare local path or uncorroborated URL never supplies portable proof. The shipped `Full-review evidence:` receipt grammar remains unchanged.

## Independent predicates and outcomes

`reviewFreshness(rec, currentWtree, ruled)` in [`lib/review-evidence.ts`](https://github.com/garrytan/gstack/blob/297f50c7e1d46aab1404f5f2e8a9584af76ad6b2/lib/review-evidence.ts#L357-L384) evaluates a diff-review row through ordered checks. An orchestrator or audit consumer must evaluate scope, completion, convergence, content binding, current working-tree equality, and clean findings independently, retaining every failed or unknown predicate rather than collapsing them into a single boolean:

| Predicate | Source check (`lib/review-evidence.ts`) | Establishes | Outcome when predicate fails or is unknown |
|---|---|---|---|
| Eligible diff-review skill | `DIFF_REVIEWS.has(rec.skill)` (`L8`, `L358`) and `rec.skill !== "ship"` (`L359`) | Row belongs to a diff-review skill (`review`, `review-fix-check`, `adversarial-review`, `codex-review`, `design-review-lite`) | Non-diff skill returns `undefined`; `skill === "ship"` returns `UNVERIFIED` (`ship telemetry is not a review pass`) |
| Unchanged content during pass | `rec.review_binding?.state !== "changed"` (`L361-L364`, set at `L307` when `start.wtree !== end`) | Working tree did not move between `--start` capture and `--finish` stamp | `STALE` (`content changed during review: the tree moved from <start> to <end> while <skill> ran...`) |
| Full review scope | `rec.scope !== "fix-range"` (`L365`; `bindReview` sets `review_binding.state = "fix-range"` and omits `wtree`/`start_wtree`/`end_wtree`, `L310-L321`) | Pass reviewed the full diff rather than a narrowed fix range | `UNVERIFIED` (`fix-range pass; only a later full pass can clear review`) |
| Captured start/end binding | `rec.review_binding?.state === "verified"` and `Boolean(rec.wtree)` and `binding.start_wtree === rec.wtree` and `binding.end_wtree === rec.wtree` (`L366-L368`) | Valid single-use start token was consumed on the same repo, branch, and unchanged `wtree` | `UNVERIFIED` (`missing start capture or incomplete/nonconverged pass`) |
| Pass completion | `rec.completed === true` (`L308`, `L366`) | Required reviewers and Step 4.7 probes completed (`review/SKILL.md:884-887`) | `UNVERIFIED` (`missing start capture or incomplete/nonconverged pass`) |
| Pass convergence | `rec.converged === true` (`L308`, `L366`) | Pass finished with zero edits (`review/SKILL.md:888`) | `UNVERIFIED` (`missing start capture or incomplete/nonconverged pass`) |
| Current candidate tree match | `Boolean(currentWtree) && currentWtree !== "unknown" && rec.wtree === currentWtree` (`L370-L372`) | Current checkout content (`bin/gstack-wtree --review`) matches the reviewed `wtree` | `STALE` (`working-tree content differs from reviewed content`) |
| Clean status and resolved findings | After `withoutRuledNotes(rec, ruled)` (`L348-L355`, `L376`): `rec.status === "clean"`, `(rec.findings_open ?? rec.issues_found) <= 0`, `rec.critical <= 0`, no unfixed `codex-review` findings, and `!rec.findings?.some(unresolvedFinding)` (`L377-L382`) | No open, blocking/critical deferred/noted, or unruled defect remains | `UNVERIFIED` (`review has unresolved findings or did not finish clean`) |
| All predicates above hold | `L383` | Historical pass integrity **and** current-candidate freshness | `CURRENT` (`completed clean pass on unchanged content`) |

Historical vs. current-candidate evidence:

- **Historical pass evidence** is established by `commit_full`, `tree`, `review_binding` (`start_wtree`, `end_wtree`, `started_at`, `branch_id`), `scope`, `completed`, `converged`, and the findings derived or stamped at log time.
- **Current-candidate freshness** additionally requires `rec.wtree === currentWtree` (with `currentWtree` known) and zero unresolved findings on a `verified`, `completed: true`, `converged: true`, full-scope row.
- **No false inference or invented expiration.** Full scope, commit equality (`commit_full === HEAD`), a cycle count (`cycles: 3`), or `completed: true` with `converged: false` never makes an upstream review row `CURRENT` or a completed baseline on its own. No wall-clock or maximum-age threshold exists in the shipped sources, and none is added here.

### Write-once mechanics, checkpoints, and late writes

- **Exclusive creation and immutability.** The inline Bun fence (`skills/review-and-prep.md:2335-2462`) writes each file with `{flag: "wx"}` (`L2431`); a second write exits `2` (`FULL_REVIEW_RECORD: exists <kind>`) and leaves existing bytes untouched (`tests/skill-protocols-review-and-prep.test.ts:1661-1672`). Neither a `continue` invocation nor a later `/review` run in the same invocation writes either file (`skills/review-and-prep.md:2317-2320`).
- **Three checkpoints (`before-fix`, `next-cycle`, `stop`).**
  1. `before-fix` runs after collection and before Step 5's first fix. A `missing` result is still inside the write window: the producer writes the record from the same collection results and rechecks before editing (`L2262-L2267`).
  2. `next-cycle` runs at the next cycle's Step 3 (cycle 2 for `cycle-1-baseline`, cycle 3 for `cycle-1-fix-review`) before any reader or probe starts. If the record is absent, the fence atomically writes `<kind>.missed.json` (`schema: "review-and-prep-record-miss/v1"`, `boundary: "next-cycle"`, `L2447-L2455`), which permanently refuses any later `provenance: "write-point"` write (`L2404`).
  3. `stop` reads both records at the three-cycle cap (`L2274`). No late write is permitted at `stop` (`L2289`, `tests/skill-protocols-review-and-prep.test.ts:1641-1658`).
- **Permitted late write at `next-cycle`.** A single late write (`provenance: "late"`) is allowed only at the `next-cycle` boundary that recorded `<kind>.missed.json`, before any reader or probe of that cycle starts (`L2278-L2291`, `L2405-L2426`). Every stage and probe value must come from retained files inside the evidence directory written during that cycle's collection that contain the cycle's snapshot SHA (`s1` or `cycle_2_snapshot`); self-references and generated `cycle-1-(baseline|fix-review)(.missed)?.json` files are refused (`L2412-L2424`). The helper records `late: {boundary: "next-cycle", miss_sha256, sources: [{path, sha256}]}`. At a cap stop, the stop's internal record and the dedicated evidence comment carry `provenance: late (next-cycle)` and the source `sha256` digests, while local file paths remain local (`L2586-L2593`).
- **Boundary between helper mechanics and coverage judgment.** The inline helper checks JSON schema, exact string flags, probe outcome consistency, late-source containment, and Git tree equality (`B^{tree} === t` and `(snapshot^{tree} === t) === snapshot_tree_equals_t`). The skill prose owns stage selection, allowed gate skips, and probe key/outcome classification (`CLAUDE.md:106-114`, `skills/review-and-prep.md:2165-2205`).

### Stop decision table, portable row corroboration, and E11 continuation path

At a three-cycle cap stop on a non-continuation full-scope invocation, the eight-row table in [`skills/review-and-prep.md`](../../skills/review-and-prep.md#when-review-stops-at-its-cycle-cap) (`L2567-L2576`) governs the receipt's `Full-review evidence:` line, with unavailable reasons chosen by first-match precedence (`record-missing` → `anchor-changed` → `reviewer-incomplete` on cycle 1 → `tree-differs` → `reviewer-incomplete` on pending fix review, `L2560-L2564`):

- **Eligible coverage rows (2 of 8):**
  1. `cycle-1-baseline` is `present` with `completed="true"` and `snapshot_tree_equals_t=true` (`cycle-1-fix-review` not read).
  2. `cycle-1-baseline` is `present` with `completed="pending-fix-review"` and `snapshot_tree_equals_t=true`, and `cycle-1-fix-review` is `present` with `cycle_1_snapshot === snapshot` and `fix_reviewed="true"`.
- **Ineligible rows (6 of 8):** missing/missed/unreadable `cycle-1-baseline` (`record-missing`); `completed="false"` from a missing `/review` anchor (`anchor-changed`) or incomplete reviewer/probe (`reviewer-incomplete`); `snapshot_tree_equals_t=false` on either `"true"` or `"pending-fix-review"` (`tree-differs`); or `"pending-fix-review"` without a matching same-snapshot `fix_reviewed="true"` record (`reviewer-incomplete`).
- **Coverage vs. clean convergence.** In the portable row `Full-review evidence: commit=<B>; tree=<T>; scope=full; completed=true; source=<durable reference>`, `completed=true` records **full-review coverage of anchor `B`**, not a clean review (`skills/review-and-prep.md:2547-2551,2589-2590`). `fix_reviewed="true"` means cycle 2 reviewed cycle 1's fixes and revalidated reproduced probes; defects still open at cycle 3 remain in `Unresolved:`. The optional upstream `review_read_row` in `cycle-1-baseline.json` is not required for `completed="true"` (`L2212-L2213`) and cannot replace stage and probe records. Conversely, a nonconverged upstream review-log row (`completed: true, converged: false`) alone is `UNVERIFIED` and never supplies a baseline without this wrapper record chain.
- **Portable corroboration and cross-host continuation.** On the first stop with available evidence, the producer posts the per-stage and probe results with `B` and `T` in a dedicated unmarked PR comment, corroborates its author, every editor (`userContentEdits`), and content, and sets `source=` to its permalink (`scheme://...`, whitespace-free, never a local path or `file://`, `skills/review-and-prep.md:2608-2625`; `docs/workflow-handoffs.md:489-505`; `tests/handoff-contract.test.ts:712-718`). Across cumulative `continuation=repair-only` runs—including on another host where local `cycle-1-baseline.json` is absent—the producer and H-E guard preserve the prior corroborated `B`, `T`, and `source=` permalink (`E-CUMULATIVE-FULL-ANCHOR`, `skills/review-and-prep.md:2530-2532,2551-2553`), independently verifying `git rev-parse "<B>^{tree}" === T` and that `Stopped at` is an ancestor of `HEAD`. A delta-only invocation start never replaces `B` (`E-CUMULATIVE-DELTA-NOT-FULL`).
- **E11 path from a capped stop to shipping.** When `/review` hits its three-cycle cap, `/review-and-prep` commits, pushes to the draft PR, posts the `<!-- review-and-prep:stopped:<full-sha> -->` comment, and emits the H-E hold prompt (`Run /review-and-prep continue ...`, status `stopped`). Under E11 ([`workflow-efficiency-program.md`](workflow-efficiency-program.md#selected-work) `L35`; [`docs/workflow-handoffs.md`](../workflow-handoffs.md#case-list) `L248`, `L251-L345`, `L1019-L1021`), only an authorized `/review-and-prep continue` run (`E-CONTINUE` or `E-USER-POLICY`) can execute the continuation, resolve the restriction in a newer corroborated running-account receipt or pause (`reviewRestrictionResolved: true`, `B-STOP-RESOLUTION-VERIFIED` or `B-STOP-RESOLVING-PAUSE-THEN-RECEIPT`), mark the PR ready, and emit the H-B `/ship-and-land` handoff. A stopped draft—even one recording `Unresolved: none recorded` (`B-STOPPED-NONE-RECORDED`)—holds against `/ship-and-land`. Neither this mapping, a passing `EvidenceBundle`, nor an agent success summary (`D-BARE`, `D-STOPPED`) clears a stop.

### Four distinct lane-verification concepts

Upstream separates provenance verification from gate-reuse eligibility across [`lib/evidence-bundle.ts`](https://github.com/garrytan/gstack/blob/297f50c7e1d46aab1404f5f2e8a9584af76ad6b2/lib/evidence-bundle.ts#L130-L244) and [`lib/tree-receipt.ts`](https://github.com/garrytan/gstack/blob/297f50c7e1d46aab1404f5f2e8a9584af76ad6b2/lib/tree-receipt.ts#L200-L243):

1. **Producer-declared verified lane (`buildBundle`, `lib/evidence-bundle.ts:141-152`):** sets `lane.verified = true` when the local ledger entry has `cmd_sha256`, `tree`, and `commit`, ran on a clean fingerprinted tree (`!lane.dirty && lane.wtree`), and `lane.commit === HEAD`. `buildBundle` checks provenance of the recorded run, not whether `lane.exit === 0`.
2. **Local-ledger verification (`verifyBundle` with `mode: "ledger"`, `lib/evidence-bundle.ts:228-237`):** confirms that the current machine's own ledger contains a matching `(label, cmd_sha256, commit)` record whose `log_path` exists on disk, matches `l.log_sha256`, and has `l.verified === true`. A bundle produced on another machine is `unverified` in `ledger` mode (`produced elsewhere; rerun to verify`).
3. **Rerun verification (`verifyBundle` with `mode: "rerun"`, `lib/evidence-bundle.ts:221-226`):** requires `HEAD^{tree} === bundle.repo.tree`, executes `l.command`, and marks the claim `verdict: "verified"` when `rerun_exit === l.exit` (`rerun exited ${exit} as recorded`). Consequently, `verifyBundle` can corroborate a recorded nonzero exit (`exit === 1` matching `l.exit === 1`), proving the failure record is accurate without making it a passing check.
4. **Tree-receipt lane reuse (`buildReceipt`, `lib/tree-receipt.ts:216-225`):** marks a lane `reusable` only when the tree diff between `gated_head` and `current_head` is `same-modulo-stamps`, predecessor head did not move, the lane is in `bundle.lanes` (never `bundle.imported`), is not in `stamp_sensitive_gates`, has `lane.verified === true`, has `lane.exit === 0` (`recorded run exited ${lane.exit}` rejects any nonzero exit), has zero `ExecutionIdentity` diffs, and all `required_lanes` are present.

### Documented structural gaps (no runtime or gate work in this card)

- **No review fields in `EvidenceBundle`.** `gstack-evidence-bundle` v1 carries command-lane and execution-identity records for `gstack-tree-receipt`; it has no fields for `gstack-review-log` rows, `review_binding`, or `/review-and-prep`'s `cycle-1-baseline.json` / `cycle-1-fix-review.json` and `Full-review evidence:` artifacts.
- **No built-in transport or cryptographic authenticity in bundle files.** Neither `EvidenceBundle` nor a SHA-256 content digest proves account authority or guarantees artifact reachability across machines. Cross-host continuation continues to rely on Git object verification (`git rev-parse "<B>^{tree}"`) and corroborated GitHub `IssueComment` author and edit-history queries (`docs/workflow-handoffs.md:455-461,497-506`). This design executes none of the verification or receipt operations above.
