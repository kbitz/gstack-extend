# Review run state (`review-run-state/v1`) and `bin/review-state`

Supporting design for [SPEC](../SPEC.md#o6-bounded-measured-stage-effort) O6.1 and [workflow efficiency program](workflow-efficiency-program.md#selected-work) item E15, reviewed by a full novel-tier `/autoplan` run and cut to the owner's ~800-line scope on 2026-11-10.

## D1. Roles

The skill decides (scope, findings, adjudication, stop decisions); the helper (`bin/review-state`) validates input shape and Git facts, stamps times, serializes, and decides nothing (`CLAUDE.md` helper boundary). A run is one `/review-and-prep` invocation and its evidence directory, including paused and resumed segments. A `continue` after a stop is a new invocation and a new run whose `start` records the continuation. `bin/review-state` and `review-run-state/v1` are experimental until Track 79A's default decision (`SPEC.md` experimental rule); `--help` says so. The state file is an internal store: external consumers keep reading the published receipts and handoff lines, never the state file.

- **Degraded path:** When the helper reports `retry: "same-input"` (`busy` or `unwritable`, waiting `retry_after_ms` when present) or exits without one parseable result line (Bun missing, uncaught error), the caller (Track 77B) reruns the identical command at most once (replay confirms a write that landed; never loop). If the rerun still does not succeed or the helper reports `bad-dir`, `unreadable` (`corrupt` or `newer-schema`), or another refusal, the caller continues that run on today's inline path and records the run state as unavailable with the reason (SPEC O6.1); under the value, outputs depend on the state only through `render`, and a refused render falls back to that output's inline text.
- **Supported storage:** Local filesystem on one host. Track 77B places state-path instructions in [`docs/review-run-state-calls.md`](../review-run-state-calls.md), loaded on demand under `run-state=record`, so the opt-in period does not grow what every review reads.

## D2. Location

Every command takes `--dir`, an absolute path to the run's existing evidence directory, and runs from inside the repository work tree (top level from `git rev-parse --show-toplevel`, stripping only the trailing newline; outside a work tree returns `refused`, reason `not-in-worktree`). Git subprocesses run with every inherited `GIT_*` environment variable removed (`tests/helpers/fixture-repo.ts`), so `GIT_DIR` or `GIT_WORK_TREE` cannot redirect Git to another repository. As in that fixture helper, global and system Git configuration are disabled; repositories that require account-level `safe.directory` configuration are not supported by this experimental helper.

- **Repository binding:** `start` binds the run to the repository's identity (the `realpath` of `git rev-parse --git-common-dir`) and branch; a later write call from another repository or branch is refused `worktree-mismatch`, while another top level of the same repository (a recreated workspace) is accepted and recorded in the new segment at `checkpoint resume`. Read-only `export` checks the repository identity but permits a different branch (D8).
- **Directory validation:** A `--dir` that is relative, missing, not a directory, a symlink in its final component (`lstat`; symlinked ancestors such as a linked home are allowed), or inside the work tree after `realpath` resolution (evidence stays outside disposable workspaces and is never committed: `SPEC.md`) is refused `bad-dir` (exit 1) with `detail.condition` (`relative`, `missing`, `not-directory`, `symlink`, `in-worktree`), the resolved real path, the top level, and a condition-specific fix (for `missing`: create it with `mkdir -p`; the helper never creates directories or computes the path). The directory is the run's per-invocation subdirectory under `<state-root>/projects/<slug>/review-and-prep/`, otherwise `~/scratch/review-and-prep/` (`skills/review-and-prep.md`, `### Evidence directory`).
- **Files:** `review-run-state.json`, its lock `review-run-state.json.lock`, and temporary files `review-run-state.json.tmp-<pid>-<hex>`, all mode `0600`. The helper also reads its checkout's `VERSION` for `helper_version` and `writer`; apart from that version read, it reads and writes nothing outside `--dir` and the Git object database.

## D3. Write protocol

1. **Parse before touching state:** Every write command takes `--input FILE`: an absolute path to a regular file (not a symlink) inside `--dir` holding one UTF-8 JSON object of at most 1 MiB. Read-only `export` takes no input file. The helper never reads stdin, so a forgotten redirect cannot hang a caller and a retry resends the same file. Evidence files named in write input are checked and hashed before taking the lock.
2. **Acquire exclusive lock:** Create `review-run-state.json.lock` exclusively (`wx`) and write `{pid, host, started_at}` into it; a permission, read-only, or no-space error returns `unwritable` (exit 3). An existing lock is retried every 50 ms for up to 5000 ms (`GSTACK_EXTEND_REVIEW_STATE_LOCK_WAIT_MS`, integer `0..60000`; any other value is a `usage` error naming the variable and range, never clamped), then returns `busy` (exit 4) naming the recorded holder (`unknown` when empty or unparseable) and the manual recovery: confirm no `review-state` process runs as the recorded pid on the recorded host, delete the lock, and rerun the same command (replay makes the rerun safe); a caller never deletes a lock without that confirmation. The helper never breaks a lock.
3. **Apply and commit under lock:** Read and validate the current state (absent only for `start`; an invalid state is `unreadable` with reason `corrupt` and is never overwritten; reading checks schema keys, types, and internal references only, so a deleted evidence file or pruned Git object never makes a stored state unreadable), apply the command, serialize canonically, write a temporary file exclusively, `fsync` it, rename it over `review-run-state.json`, and remove the lock.
4. **Commit point and cleanup:** The rename is the commit point. A failure before it, including writing or syncing the newly created lock, removes the helper's temporary file and lock, leaving previous state bytes untouched. A failure after it (removing the lock) still reports `recorded` with `detail.warnings`. Git bindings are sampled after acquiring the lock; the tree is resolved from the captured commit SHA rather than a second moving `HEAD` read.

## D4. Replay

Every record carries a caller-stable ID (`run_id`, `pass_id`, `correction_id`, `gate_id`, `audit_id`, `checkpoint_id`; a run has one `finish`). The same ID with identical caller input returns `replayed` (exit 0, no write); the same ID with different caller input returns `conflict` (exit 1). Replay compares stored caller fields (`C` in D6) against the canonicalized new input; helper-stamped fields (`H` and `G` in D6: helper times, Git-stamped heads and trees) are excluded while caller-observed times are compared. `conflict` reports the first differing JSON path with stored and sent values cut to 80 characters. `recorded` and `replayed` both return helper-stamped `head`, `tree`, and `recorded_at` in `detail`; a replayed `finish` whose stored head differs from current `HEAD` adds `detail.head_moved: true`.

- **Check order:** (1) arguments and input shape, (2) replay lookup (an identical earlier record is `replayed` in any lifecycle state, including while paused or after finish; for `start`, the same `run_id` with identical input is `replayed` in any later state, different input is `conflict`, and a different `run_id` is refused `exists`), (3) lifecycle state (`not-started`, `paused`, `finished`), (4) environment validation (Git objects exist, evidence files exist inside `--dir` with matching digests).
- **Immutable pass, correction, gate, and audit records:** Passes follow the workflow-metrics state model (`bin/lib/workflow_metrics.py`): `record pass` with `state` `started` (replay key `pass_id + state`), `attempt` (`pass_id + voice_id + attempt_id`), `voice-complete` (`pass_id + voice_id`), and `completed` (`pass_id + state`). Later finding adjudication or resolution is recorded via `record correction` (`correction` extends the card's `pass|gate|audit` record types and never sets `adjudication: "duplicate"`). Gates and audits are append-only; for derivation, the last record in array order per gate or audit `name` is current.

## D5. Lifecycle

```text
  (absent) --start--> OPEN (segment 1)
  OPEN   --record / checkpoint (any kind but pause or resume)--> OPEN
  OPEN   --checkpoint pause--> PAUSED        (ends the segment)
  OPEN   --checkpoint resume--> OPEN         (closes previous segment as "interrupted" at its last helper-stamped write; opens segment n+1; refuses same non-null session_id)
  PAUSED --checkpoint resume--> OPEN         (segment n+1; takes its telemetry session id)
  OPEN   --finish prepared|stopped|blocked|needs-context--> FINISHED
  PAUSED --record / finish / other checkpoint--> refused "paused"
  FINISHED --any write but an identical finish--> refused "finished"
  (absent) --record / checkpoint / finish--> refused "not-started"
  any state --start, same run_id, identical input--> replayed (no write)
  any state --start, same run_id, different input--> conflict
  any state --start, different run_id--> refused "exists"
  any state --any record, checkpoint or finish identical to an earlier one--> replayed (checked before lifecycle)
```

Checkpoint `kind` is a closed v1 enum: `before-fix`, `next-cycle`, `stop`, `pause`, `resume`, `external-gate`, `ready`. Only `pause` and `resume` transition the lifecycle (`resume` on an `OPEN` run closes the interrupted segment at its last helper-stamped write and opens segment `n+1`, refusing `same-session-resume` when a non-null `session_id` matches the open segment's); the others are stored and `external-gate` and `ready` feed rendering. A pass is open from `started` to `completed`: an `attempt` or `voice-complete` for an unknown or closed pass is refused `invalid-input`; a new attempt on a voice already closed by `voice-complete` is also refused (an identical retry still replays), and `finish` with `outcome: "prepared"` while any pass is open is refused `invalid-input` (`stopped`, `blocked`, or `needs-context` may leave a pass open).

A state file with `schema: "review-run-state/v<N>"` where `N > 1`, or a `review-run-state/v1` file that fails validation whose `writer` is a valid 3- or 4-part numeric version string strictly newer than `helper_version` (padded 4-tuple comparison), is rejected as `unreadable` with reason `newer-schema` (exit 1); an unknown, missing, or mistyped field with an equal, older, `null`, or malformed `writer` is `unreadable` with reason `corrupt`.
An older helper that does not recognize `segments.end: "interrupted"` reports `newer-schema` when the stored writer is newer; the current helper accepts that end value. `show.writer` is the stored writer and `show.helper_version` is the executing helper version, or `null` when unavailable.

- **Derived segment identity and UUIDv5 namespace (`NAMESPACE`):** `export` and `derive` share the fixed UUIDv5 namespace `9aa572eb-215f-452f-99e8-2bfdf0329cf3` (`src/review-state/export.ts`, `bin/lib/workflow_metrics.py`). - **Write-once baseline records:** `cycle-1-baseline.json` and `cycle-1-fix-review.json` stay with the skill's existing write-once fence (`skills/review-and-prep.md`, `### Record cycle 1's full-review baseline`); the state references them in `evidence` by relative path and `sha256` and never rewrites them.

## D7. Validation rules

In new input, unknown keys, missing required keys, wrong types, and out-of-enum values are refused (`invalid-input`) with the JSON path; omitted optional keys take their D13 default. Identifiers use the workflow-metrics grammar (`SAFE_ID_RE`, `VOICE_RE`, `PART_RE`, `DELEGATE_LABEL_RE`, `UUID_RE`); SHAs are 40 or 64 lowercase hex; timestamps are UTC ISO 8601 ending in `Z`; strings have length bounds and forbid control characters (`\u0000`–`\u001f`, `\u007f`); URLs (`run.pr.url`, `details.run`) require `https://` or `http://` with no whitespace, userinfo, or query string, while `full_review_evidence.source` accepts any whitespace-free URI or resource reference (`1..500` chars, no control chars or userinfo); `evidence` paths are relative, resolve inside `--dir`, and name regular files matching `sha256`; the same checks cover `pregate.details.record_path`/`record_sha256` and documentation `details.section_path`/`section_sha256`. Cross-field rules: metrics v2/v3 rules for attempts, delegates (`credited` iff `completed` and `fallback_reason: null`; `fell-back` iff `failed` and `fallback_reason` set; `wall_ms`, `input_tokens`, `output_tokens`, and `cache_read_input_tokens` are integers `>=0`, and only `cache_creation_input_tokens` may be `null`; a delegated attempt requires its voice's `part` from `attempt.part` to match `PART_RE`; non-null parts on one voice must agree, null parts on native fallback attempts preserve its established label), `found_by` (non-empty requires `attribution_reason: null`; empty requires an enum reason; never `specialist:red-team`), and duplicates (`adjudication` in `rejected|duplicate` requires `resolution: "unknown"`; `duplicate` requires `duplicate_of != finding_id`); `policy.delegation` when `status === "active"` requires non-empty `parts` and `tools` where each entry is a `delegate=` part name (stored as its part label: `specialist:<name>` for `testing`, `maintainability`, `performance`, and `simplification`, `native-adversarial` for `adversarial`, and `red-team` for `red-team`) or a `PART_RE` label stored as sent, with uniqueness on `parts` and `tools` and `tools` as a subset of `parts` applied to the stored labels, plus 64-hex `config` (or when `"inactive"`, `reason` `1..200`); `checkpoint` with `kind: "external-gate"` or `"pause"` requires a 40-hex `base`, and `kind: "ready"` requires a 40-hex `base` that is an ancestor of the stamped `head`; `selected_attempt_id` names a completed attempt of that voice; `predecessor_attempt_id` names an earlier attempt of that voice; `delta_from` is non-null iff `coverage === "delta"`; a correction targets an existing finding, never sets `duplicate`, and `supersedes` chains linearly; candidate and binding commits must exist in Git (`git cat-file -e <sha>^{commit}`), and `finish.base` must be an ancestor of `finish.head`.

## D8. Commands, result envelope, and reason codes

Commands: `start`, `record pass|correction|gate|audit`, `checkpoint`, `finish` (each requiring `--dir DIR --input FILE`), `show --dir DIR [--base SHA] [--wtree TOKEN]` (read-only and lock-free; validates `--dir`, `review-run-state.json`, and both `run.repo` and `run.branch`, plus optional `--base` as an existing 40-hex commit and `--wtree` against `WTREE_RE`, returning the standard refusal/unreadable/usage envelope on error and printing one `"schema": "review-state-show/v1"` JSON line `{schema, state_path, rev, writer, helper_version, lifecycle, exit, run, binding, head, plan, policy, continuation, segments, checkpoints, last_checkpoint, passes, gates, audits, unresolved, finish, rendered}` on exit 0), `render --dir DIR --input FILE` (read-only on the state and lock-free like `export`, creating `full-receipt-<n>.md`, `comment-<receipt|paused|stopped>-<n>.md`, `pr-body-<n>.md` or `final-<n>.md` exclusively with mode `0600` in `--dir` and re-reading the bytes; success prints one `review-state-render/v1` JSON line `{schema, output, exit, files: [{path, display, sha256, bytes, chars}]}` on exit 0; refusals use the standard envelope with `invalid-input` rules — `not-renderable`, `stale-ready`, `greptile-gate-missing`, `skipped-pregate-lanes-too-long`, `receipt-mismatch`, `conflicts-with-state`, `forbidden-for-exit`, and the evidence-file rules — or `unwritable`), `export --dir DIR` (takes no `--input` and acquires no lock; validates `--dir`, `review-run-state.json`, and `run.repo` without comparing `run.branch`, returning the standard refusal/unreadable envelope on error and printing one `"schema": "review-state-export/v1"` JSON line `{schema, run, segments, skipped, records, stage_runs}` on exit 0), plus `--version` (prints `review-state <version or unknown>` on stdout and exits 0), `--help`, and `<command> --help`. Every non-help, non-version write invocation (and every `show`, `export`, or `render` refusal) prints one JSON line on stdout (`{"v":1,"command","status","reason","detail","fix","state_path","rev","helper_version","side_effects","retry","retry_after_ms"}`), where `helper_version` is the checkout's `VERSION` string (or `null`), `side_effects` is `"committed"` for `recorded` and `"none"` otherwise, `retry` is `"no" | "same-input" | "after-fix" | "never"`, and `retry_after_ms` is `lockWaitMs` for `busy` and `null` otherwise. Non-successes write `ERROR <CODE>: <what>` and `FIX: <fix>` on stderr. Echoed values in `detail` are truncated to 80 characters. Launcher: three-line `exec bun --no-env-file --no-install --config=/dev/null` (`bin/outside-review` pattern).

## D11. Relation to upstream and alternatives considered

The run state is internal to one `/review-and-prep` invocation and is not a portable evidence envelope (efficiency item E10 forbids another envelope format; [`docs/designs/review-evidence-envelope.md`](review-evidence-envelope.md) remains the portable reference). It does not extend upstream's `gstack-review-log` (which binds a single `/review` pass): the caller passes upstream's `wtree` token (`gstack-wtree --review`) as input, and `bin/review-state` imports nothing from upstream, so `bin/upstream-check` gains no entry.

- **Alternatives considered and not built here:** (1) read-only `show` is implemented in Track 79A part 1 (`src/review-state/show.ts`), while a separate `next` subcommand is not built because `show` plus [`docs/review-run-state-calls.md`](../review-run-state-calls.md) (`## Resume`) give the skill the checkpoint, `head` relation, and gate freshness directly without putting workflow decisions inside the helper (`CLAUDE.md` helper boundary); (2) `flock` process locks (absent from Bun `node:fs`; FFI is platform-specific); (3) batching existing inline writes or trimming instructions without a state (fails to recover records lost in a sandboxed first segment); (4) per-record `link()` claim files without a state file (cannot enforce `finish`, segment transitions, and run-wide ordering in one consistent document); (5) a Python helper alongside `workflow_metrics.py` (rejected for this Track because the card places the helper in `src/review-state/` and Tracks 78A/79A import its TypeScript reader). Exclusive lock and atomic write helpers are implemented directly in `src/review-state/store.ts` without importing private merge-gate helpers.

## D14. Deferred decisions and Track 79A part 1 / part 2 placement (2026-11-13)

- **Retry hints** (`side_effects`, `retry`, `retry_after_ms`, and D1's single-retry caller bound): **Implemented in Track 77B (first PR)** so the opt-in caller has a deterministic retry contract without branching on individual reason codes.

- **Metrics-writer parity test:** **Implemented in Track 77B (second PR)** alongside the projection of state records to metrics records (`src/review-state/export.ts`, `bin/lib/telemetry.py`, `bin/lib/workflow_metrics.py`); the opt-in `/review-and-prep` caller follows in Track 77B's third PR.
- **Read-only `show` and interrupted-session resume (`end: "interrupted"`):** **Implemented in Track 79A (part 1)** (`src/review-state/show.ts`, `src/review-state/state.ts`, `src/review-state/export.ts`, [`docs/review-run-state-calls.md`](../review-run-state-calls.md) `## Resume`) so resume after any checkpoint or interrupted session reads the state without rebuilding receipts or gate evidence and recovers the 113A cycle-1 baseline failure mode.
- **Automatic stale-lock reclamation** (`link()` lock creation with token, boot id, and pid namespace; rename-verify-restore breaking; writer own-token recheck before commit): **Placed in Track 79A (part 2 — default decision)** because default promotion requires unattended runs not to depend on manual lock cleanup; while `run-state=record` remains opt-in, a `busy` lock after one retry logs `Run state: unavailable (busy)` and continues inline (D1).

- **Internal-error result** (`status: "error"`, exit 5, compact stderr trace, trace file in `--dir`, and guarded launcher JSON `unavailable` line): **Placed in Track 79A (part 2 — default decision)** because default promotion requires bounding any uncaught helper error seen in real runs; during opt-in, a missing or unparseable result line is retried at most once and then falls back inline (D1).
